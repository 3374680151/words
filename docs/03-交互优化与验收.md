## 一、九态覆盖矩阵（每模块 × 九种状态 → 实现方案）

> 九态：初始 / 加载 / 正常 / 空数据 / 提交（处理中）/ 成功 / 失败 / 禁用 / 异常恢复。
> 标注「原」= 原项目已有，平移即可；标注「🆕」= 原项目缺失，本次必须补齐。

### 1.1 打字主流程

| 状态 | 方案 |
|---|---|
| 初始 | 「原」词表就绪、未开始：WordPanel 遮罩 + "按任意键开始" |
| 加载 | 「原」居中 spinner；「🆕」失败与空态分离（见下） |
| 正常 | 「原」打字态：字母变色 / 计时器 / 进度条 / 上下词预览 |
| 空数据 | 「🆕」本章 0 词：EmptyState + "回到词书选择"（原项目死转圈） |
| 提交 | 「原」单条记录保存 `isSavingRecord` 状态机（防章节记录提前落库）；「🆕」保存中结果页按钮防连点 |
| 成功 | 「原」confetti 双侧发射 + ResultScreen 三档评语 |
| 失败 | 「🆕」`saveWordRecord/saveChapterRecord` 写 IndexedDB 失败 → error Toast（"练习记录保存失败，请检查浏览器存储"），不打断练习 |
| 禁用 | 「原」复习模式：下一章/重打/默写按钮禁用、章节 Listbox 不渲染；StartButton isLoading 时无效 |
| 异常恢复 | 「原」blur 自动暂停（回来按任意键继续）；「🆕」词表请求失败 → 重试按钮；dictId 非法自动回 cet4 + chapter 0；chapter 越界回 0（watchEffect 守卫） |

## 二、原项目缺失 → 本次补强清单（优先级分级）

### P0（规范硬性要求，缺一不可）

1. **Toast 通知系统**替代全部 `alert()`：①输入法检测提示（destructive 常驻）②导出失败 ③导入失败 ④记录保存失败。
2. **删除二次确认**：错题本行删除、词书页 ErrorTable 删除 → AppAlertDialog。
3. **错题本空状态**：EmptyState + "去练习"引导。
4. **打字页词表加载失败态**：错误卡片 + 重试按钮。
5. **统计页加载态**：查询期间骨架卡。
6. **结果页按钮防连点**（200ms 防抖 / 提交中禁用）。
7. **IndexedDB 写入失败处理**：单词/章节记录落库失败 → error Toast，不打断流程。
8. **Dialog 与全局热键冲突修复**：`activeDialogCount` 守卫，Dialog 打开时禁用页面级 Enter/Esc。
9. **导入前二次确认 + 解压失败保护**：确认弹窗明示"将清空并覆盖"；解压失败不执行覆盖。
10. **统一 AppSpinner**（消灭复制粘贴 spinner）+ **统一 AppTooltip**（三套合一）。

### P1（体验提升，Phase 5~6 落地）

1. **Dexie liveQuery 自动刷新**：错题本/统计/词书进度练习后自动更新。
2. **发音内存缓存**（Map），替代 head 挂 audio 预取 hack；预取下一词保留。
3. **Drawer 响应式宽度** `min(35rem, 92vw)`。
4. **WordCard 复制按钮** + "已复制"反馈。
5. **章节卡选中判定修复**（非当前词书误标绿第 1 章）。
6. **错题本删除后页码回退**。
7. **词书搜索框**（防抖 300ms，name/description/tags 过滤）。
8. **设置弹窗记忆上次 Tab**。
9. **ShortcutsDialog 快捷键帮助面板**（`?` 键 / 设置内入口；数据源集中常量表）。
10. **错题本排序/页码持久化**。
11. **AppKbd 统一快捷键键帽样式**。

### P2（可选，按需取舍）

1. Mobile 营销落地页平移（含轮播）。
2. DonateCard / StarCard / EnhancedPromotionModal 营销组件（后者两个原项目已未挂载，建议不迁）。
3. 埋点体系（mixpanel/GA/Vercel）——自用项目建议移除，调用点收敛到空实现。
4. 输入法 composition 支持（原项目预留未实现的 `composition` action）。
5. 埋点位（InfoPanel/donate/share 等触发点）保留形状不保留上报。
