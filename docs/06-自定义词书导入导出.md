# qwerty-learner Vue 版 · 第六部分：自定义词书导入导出（设计与施工规划）

> 回答三个问题：**做什么**（不背单词式自定义词书：纯词 txt + 带释义 CSV/Excel 双通道，可再导出）、**怎么接**（ECDICT 开源词典本地反查补释义，IndexedDB v4 落库，Gallery 零特判融入既有链路）、**怎么验收**（九态矩阵 + 新增 C 组红线 + 工单检查单）。

---

## 一、需求定位

| 项 | 内容 |
|---|---|
| 目标 | 用户可把自有单词列表（不背单词生词本导出、Excel 背表、课程词表等）导入为「我的词书」，与内置词书走**完全相同**的练习/错题/复习/统计链路，并可再导出迁移 |
| 参照 | 不背单词：导入只传单词文本（服务端词典反查补全释义）；导出仅限自制词书 |
| 本项目差异 | 无授权词典后端 → 用开源 **ECDICT**（340 万+ 词条，含中文释义/英美音标）做**本地反查库**，离线补全；同时提供 CSV/Excel 带释义列的完整通道兜底 |
| 非目标 | 不做在线词典 API（速率/离线不可控）；不做词书市场/分享码；不迁 Mobile 营销页（P2 仍挂起） |

**前置依赖（硬性）**：工单 C3 回归前必须先修复已确诊缺陷 **A（换词不自动发音）**，建议同批修 **B（复习模式刷新空白）**——否则新功能的验收会被核心体验缺陷污染。

## 二、双通道格式设计

### 2.1 导入通道

| 通道 | 格式 | 解析规则 | 释义来源 |
|---|---|---|---|
| A 极简通道 | `.txt`，UTF-8，**每行一个单词**（`#` 开头行为注释，容忍空行/首尾空格/全角空格） | 逐行 trim → 非空且非注释即一词；上限 **5000 词**、文件 **≤2MB** | ECDICT 反查补全 |
| B 完整通道 | `.csv` / `.xlsx`，首行表头可选，列序自适应：`单词, 释义, 音标(可选)`；释义列内的多义项以 `；` / `;` / `\n` 分隔 | 复用既有依赖 `xlsx`（0.18，已随结果页导出引入，零新增依赖）；CSV 按逗号/引号标准解析，UTF-8 **带 BOM 容错** | 文件自带（音标缺省再查 ECDICT） |

### 2.2 释义补全（ECDICT 精简反查库）

| 项 | 方案 |
|---|---|
| 数据构建 | 构建脚本（工单 C0）从 ECDICT 全量 CSV 取**词频前 5 万词**，字段裁剪为 `word / translation / phonetic / usphonetic`，产出 `public/dicts/ecdict-mini.json`（预估 6~9MB，gzip 约 2~3MB） |
| 加载策略 | **首次进入导入向导时**懒加载（动态 import），加载一次后写入 IndexedDB `ecdictCache` 表常驻；失败可重试，**不阻塞通道 B** |
| 反查规则 | headword 精确匹配（区分大小写先精确后小写兜底）；`translation` 按 `\n` 拆分为 `trans[]`；`usphonetic → usphone`、`phonetic → ukphone` |
| 查不到 | 词条标记「未收录」：进预览清单可**内联补释义**（可空，空释义允许导入但打字页释义区显示占位"—"） |
| 体积红线 | `ecdict-mini.json` 不进主包（动态 import 独立 chunk）；主包增量 0KB |

### 2.3 导出通道

- 自定义词书详情弹窗提供「导出 CSV」（`word,trans,usphone,ukphone`，多义项用 `；` 连接）与「导出 JSON」（直接落库结构）
- CSV 加 **BOM 头**（防 Excel 中文乱码）；文件名 `{词书名}_{日期}.csv`
- 内置词书**不提供**导出（版权边界，与「非目标」一致）

## 三、数据模型与链路改动

### 3.1 IndexedDB v4（`src/utils/db/index.ts`）

```ts
this.version(4).stores({
  ...v3,                       // wordRecords / chapterRecords / reviewRecords 原样
  userDicts: 'id, createdAt',  // keyPath 'id'
  ecdictCache: 'word',         // ECDICT 精简反查表（懒加载后常驻）
})
```

`userDicts` 单条结构（词书 ≤5000 词，单记录 blob 无压力，不做词表分表）：

```ts
type UserDict = {
  id: string            // `user_${Date.now()}`（与内置 id 空间隔离，前缀判别）
  name: string          // 用户输入，重名自动追加 (2)
  description: string   // 默认 `自定义词书 · ${wordCount} 词`
  words: Word[]         // 内部统一结构 { name, trans[], usphone, ukphone }
  createdAt: number
  updatedAt: number
}
```

**兼容性红线**：v4 升级不得改动 v1~v3 store 定义（老用户数据无缝；与 2A 工单口径一致）。

### 3.2 词书资源融合（`src/resources/dictionary.ts` + `src/stores/dict.ts`）

- 新增 `useCustomDicts()`（Pinia，挂 `dict` store 内或独立）：启动时从 `userDicts` 读全量 → 产出 `Dictionary[]`（`url: ''`、`category: '我的词书'`、`tags: ['自定义']`、`language/languageCategory: 'en'`、`length = words.length`）
- `idDictionaryMap` 消费点改造：`dictInfo` computed 改为「静态表 + 自定义表」合成查找（自定义表优先级低于静态表，id 前缀 `user_` 隔离冲突）；Gallery 分组渲染在静态分类之后追加「我的词书」组
- 章节切分沿用 `CHAPTER_LENGTH = 20` + `calcChapterCount`，零新逻辑

### 3.3 词表加载分支（`src/composables/useDictWords.ts`）

```ts
// 伪代码：isCustom = id.startsWith('user_')
if (isCustom) { raw = await db.userDicts.get(id).words }   // 不走 fetch(url)
else { 现有 fetchWithCache(url) 不动 }
```

- 内存缓存复用 `wordListCache`（key 换成 dictId）
- 首章内置词分支仅对 `cet4` 生效（自定义书不触发，红线 17 不受影响）
- `trans` 兜底清洗（红线 21）天然覆盖空释义场景

### 3.4 打字链路

`Typing` 页、`WordPanel`、错题本、复习、统计**零改动**——`wordRecord.dict / chapterRecord.dictId` 存的是词书 id 字符串，自定义书 id 天然兼容；发音按 `name` 文本走有道 API，不依赖音标字段。

## 四、交互设计（导入向导 + 我的词书）

### 4.1 导入向导（AppDialog 三步式）

| 态 | 方案 |
|---|---|
| 初始 | 拖拽区 + 点选上传；明示格式与上限（「txt 每行一词 / CSV·Excel 三列」/ ≤2MB / ≤5000 词） |
| 加载 | 解析进度 + ECDICT 首次加载进度（两段文案区分）；可取消 |
| 识别结果 | 统计条：`成功 N · 未收录 M · 去重 K`；预览表格前 50 条（词/释义/音标/来源标记），未收录行**内联编辑释义**；K>0 给出去重说明 |
| 空数据 | 文件无有效词 → error Toast「未识别到有效单词，请检查格式」+ 不落库 |
| 提交 | 命名输入框（默认取文件名，重名自动 `(2)` 并提示）→「确认导入」loading + 防连点 |
| 成功 | success Toast → 弹窗关闭 → 我的词书组自动展开并定位新书 |
| 失败 | 解析失败/写库失败 → error Toast，**不产生半本词书**（事务写入） |
| 禁用 | 提交中按钮禁用；关闭弹窗 = 取消（任意步骤可退，不落库） |
| 异常恢复 | ECDICT 加载失败 → 通道 A 降级为「全部未收录」，引导补释义；写库失败可重试 |

### 4.2 我的词书（Gallery 集成）

- 语言 Tab 区之后新增「我的词书」分组（空态：插画 +「导入你的第一份词书」按钮）；导入入口常驻分组头（+ 按钮）
- 卡片/章节 Dialog/错题 Tab/复习面板 **复用既有组件零特判**（SpotlightCard、懒查统计、章节懒加载全部继承）
- 词书详情弹窗右上角新增两个图标按钮：**导出**（下拉 CSV/JSON）、**删除**
- 删除：AppAlertDialog 二次确认，文案明示「练习记录与错题保留（错题本/统计仍可见），词书本体不可恢复」；若当前正在练此书 → 确认后 `currentDictId` 回落 cet4（对齐红线 17 语义）

### 4.3 新增交互红线（C 组，验收逐条对照）

| # | 红线 |
|---|---|
| C1 | 导入向导任意步骤可取消，关闭即中止，**不落库** |
| C2 | 书内重复词去重并在统计条明示数量 |
| C3 | 词书重名自动加后缀 `(2)` 并 toast 提示 |
| C4 | 空文件/无有效词/超上限 → 明确错误 Toast + 不落库 |
| C5 | 词表事务写入，失败不产生半本词书 |
| C6 | 自定义书产生的 wordRecord/chapterRecord/reviewRecords 与内置书**同构**（错题本/统计/复习零特判） |
| C7 | 章节切分 20/章与内置一致；`currentChapter` 越界守卫同样生效 |
| C8 | 删除二次确认；正在练的书删除后回落 cet4 |
| C9 | 导出 CSV 带 BOM；文件名含词书名与日期 |
| C10 | `ecdict-mini` 独立 chunk 不进主包；懒加载失败降级不阻塞通道 B |

## 六、验收对照表（对照开发规范第七、八节）

| 规范条款 | 验证方式 | 通过标准 |
|---|---|---|
| 按参考项目对照 | 不背单词导入流程并排走查（上传→识别→确认三步语义） | 步骤等价或更优 |
| 实际执行每一种操作 | txt/CSV/xlsx 三样本全流程 + 导出再导入回环 | 导出→清库→导入→练习记录与词书完整还原 |
| 成功/失败场景 | 坏 CSV、空 txt、5 万词超大文件、断网懒加载 | 全部可见错误态，可恢复，无白屏 |
| 空数据 | 首次打开（零自定义书）、全部未收录 | 空态引导 + 内联补释义可用 |
| 加载与重复提交 | 提交中连点「确认导入」 | 防连点，单书单条 |
| 弹窗关闭与状态 | 四种关闭方式 × 任意步骤 | 状态合理，重开回 Step1，无残留遮罩 |
| 列表刷新 | 导入成功后 Gallery/统计 | 我的词书组即时出现，计数正确 |
| 数据一致 | 2A 口径复测：v3 老数据 + v4 混合读写 | 老数据无感，练习记录可被原项目读回（schema 兼容） |
| 类型与构建 | `pnpm typecheck` + `pnpm build` | 零错误；主包 gzip 增量 ≤ 10KB |
