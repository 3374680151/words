## 二、自测发现并修复的应用层真 Bug（3 个）

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| 1 | **repeatChapter 抛 DataCloneError** | Vue reactive Proxy 不能 structuredClone（原项目 immer draft 是普通对象） | replaceState 改 JSON 深拷贝 |
| 2 | **复习进度未落库** | putWordReviewRecord 未 await 内部 put（原项目就有的隐患）+ 展开拷贝后自增 id 未回写原对象 | await put + 返回 id + startReview 回写 record.id |
| 3 | **嵌套 Proxy 进 IndexedDB 抛 DataCloneError** | Vue 深层 reactive 使 record.words 成为 Proxy 数组，顶层展开不够 | 三处写入（word/chapter/review record）统一 JSON 深拷贝后 add/put |

测试方法教训（写入流程）：
- 页面模块图与 evaluate 动态导入必须同源（无 query 导入 + testkit 转出口保证 pinia 单实例），否则 Pinia 按 id 去重会返回旧代码创建的 store 实例。
- 断言期望值要按原算法重新推演（加权排序输出 w2,w1,w3 是正确行为；tick 时 wordCount=0 → wpm=0 正确）。
- 中断运行会残留测试数据，断言避免写死数量（>=1 + 全字段校验）。
